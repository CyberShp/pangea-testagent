# 网卡极限带宽测试

平台提供场景入口和负载管理。执行前读取 [运行流程](references/runbook.md)。所有设备操作通过 testagent 工具执行并遵守分阶段 preview。测试人员选择目标与设备，由 Agent 探测和解释适用方案。

默认保持现有绑定，TCP 每对 4 条并发、测量 60 秒、预热 3 秒，依次测正向与反向。整卡模式每方向同时运行两对 iperf3。每对绑定明确的测试 IP、监听端口和接口。目标带宽 0 表示仅测量，正数表示该方向的单端口或整卡目标 Gbit/s。

先确认网卡、地址、路由、对端、架构及工具依赖，预览部署与负载参数，取得确认再运行。参数未满足时 ask，不猜测内网配置。按 workload 声明使用平台 load_start、load_wait、load_status、load_stop；实时曲线与原始日志由平台采集。每轮使用唯一负载名称。

未达标时给出一个有证据的建议，说明将改什么与理由，等待用户确认新的操作预览后复测。绑核使用 load.cpus，IRQ 调整使用 tune_apply；恢复用 tune_restore 并回读。不要自行连续搜索配置。报告保留未改善或失败的轮次。

完成前确认所有负载退出、调优恢复；检查点引用真实 operation_id。生成结果报告，包含环境、每轮配置、测量指标、目标判断、证据和未验证条件。完整测量与性能达标分别表达；只有接收均值、瞬时采样或有限条件时，不断言硬件绝对极限。
